## 本リポジトリについて

このリポジトリは **公開 OSS** です（`japanese-web-ui-quality-gate`）。日本向け Web UI の
レビュー・品質ゲートとして使う agent skill（`SKILL.md` 形式、Codex / Claude Code / Gemini CLI /
GitHub Copilot など複数ランタイムで読める）を、公開に耐える形で管理しています。upstream の
利用者（他リポジトリ・他エージェントからこの skill を導入する第三者）がいる前提で、README・
`SKILL.md`・`references/checklist.md`・`examples/` の一貫性と、秘密情報・私的パス・私的運用
情報を含まないことが継続的な品質基準です。

## 役割分担（モデル固定名を使わない）

- **司令塔**: 要件再定義・設計判断・レビュー・実装者への委譲文作成を担当する role。
- **実装**: 通常タスクは `codex` 相当の実装エージェント、難所のみ deep-reasoning 版
  （xhigh 相当）に委譲する。
- **並列調査・機械的作業**: サブエージェント（並列 fan-out 調査、mechanical な棚卸し等）に
  委譲する。
- **フロントエンド/UI**: 専用のフロントエンド実装エージェントに委譲する。本リポジトリは
  自体が UI 実装を含まない skill リポジトリのため、現時点でこの分担は該当しない
  （`AGENTS.md` の「ビジュアルデザインはエージェントが創出せず、デザインブリーフを書いて
  停止する」方針とも整合）。

固定モデル名を運用ルールの恒常記述に使わないこと。役割名で書く。

## 調査範囲と注意（引き継ぎ時点の限界）

- 根拠は local git 状態と、repo 内の `AGENTS.md` / `HANDOFF.md` / `TASKS_BACKLOG.md` /
  README / `SKILL.md` / `references/checklist.md` / `examples/` の読み取り専用調査のみ。
- GitHub Actions の実行結果、外部ランタイムでの実際のインストール・読み込み挙動は、
  repo 内の記録（HANDOFF.md のコマンド結果ログ等）を根拠とし、それ以外は未確認として扱う。
- 秘密情報・トークン・実運用ログ・私的リポジトリ名・ローカル絶対パスは、このリポジトリの
  性質上そもそも repo に存在してはならない（`scripts/scan-private-markers.ps1` が継続的に
  検証する）。引き継ぎ作業でもこれらを新規に持ち込まない。
- 既存資料は現状把握の材料であり、要件定義の最終正本ではない。市場動向・他ランタイムの
  仕様は陳腐化を疑って必要に応じ再確認する。

## 主要ファイル（reading order）

1. `AGENTS.md` — 自律エージェント運用契約（タスク選定→実装→自己検証→コミット→PR→マージの
   自走範囲、4つの人間承認ゲート、フロントデザインブリーフ方針などを規定）
2. `HANDOFF.md` — 現況スナップショット、完了タスク一覧、既知の問題、次アクション候補
3. `TASKS_BACKLOG.md` — タスク一覧・優先度
4. `README.md` — skill の概要・7評価軸・インストール手順・検証手順
5. `SKILL.md` / `references/checklist.md` — skill 本体と詳細チェックリスト（80項目）
6. `examples/` — 合成の適用例（実データではない）

## 現在地（引き継ぎ時点）

- 既定ブランチは `main`。直近は評価軸 v2（7軸構成、80項目チェックリスト）の実装が
  マージ済みで、`HANDOFF.md` に完了タスク一覧・検証コマンド結果・次アクション候補が
  記録されている。詳細は `HANDOFF.md` を参照し、都度の最新状態を repo 側の記録で確認する
  こと（本書はスナップショットの要約であり、正本ではない）。
- ローカル検証はビルドステップを持たず、PowerShell スクリプト3本
  （`scripts/test-public-readiness.ps1` / `scripts/test-scan-private-markers.ps1` /
  `scripts/scan-private-markers.ps1`）と GitHub Actions（`validation.yml`）で行う。

## 次アクション候補（HANDOFF.md 記載時点）

1. 適用例（`examples/`）の拡充。日本語フォームの合成レビュー例を増やし、良い UI を
   不当に落とさない事例も含める。優先度は中程度として記録されている。
2. 既存ドキュメント・挙動の不整合や陳腐化を探し、次の1件として解消する。
   PR番号だけを追い続ける自己同期作業は優先タスクにしない。
3. リリース（バージョンタグ等）やカタログ掲載は、下記ゲート①・Non-Goals によりスコープ外。
4. 下記ゲートに該当する変更が必要になったら、実装を進めず承認を求めて停止する。

これらは記録時点の候補であり、着手前に `HANDOFF.md` / `TASKS_BACKLOG.md` の最新版で
状態が変わっていないか確認すること。

## Stop only when（人間承認が必要な境界）

`AGENTS.md` が定める4つのゲートを維持する。

1. デプロイ・GitHub Actions のワークフロー変更・release/tag 作成
2. 課金が発生する操作・有料 API の実行
3. secret・実素材・実データの外部送信
4. skill が判定する製品要件（評価軸・チェックリストの意味）そのものの変更

これらに該当しない、ローカルの実装・テスト・ドキュメント同期・self-review・コミット・
PR 作成・マージは自走してよい。フロントの視覚デザイン創出は行わず、必要ならデザイン
ブリーフを書いて停止し人手の外部デザイン工程に渡す。

## 委譲時の注意

実装や調査を他のエージェントに委譲する際は、self-contained なプロンプト（対象ファイル・
受け入れ条件・検証コマンド・書き込み許可範囲を明記したもの）を渡し、再委譲を許可しない
文言を含め、委譲先からの完了報告だけでなく成果物（diff・ファイル・テスト結果）の実在を
確認してから次へ進む。公開 OSS リポジトリである性質上、委譲プロンプト自体にも秘密情報・
私的パス・私的運用情報を含めない。
